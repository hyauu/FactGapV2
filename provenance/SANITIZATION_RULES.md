# Sanitization rules and hash scope

1. The exact supplied eight-page PDF, selected manuscript source, bibliography, author block and figure assets are unchanged. The authors' two confirmed emails are intentional public contacts.
2. Scored queries, candidate text, local numeric scores, final evaluation labels, generator/draw parameters and request bodies are preserved. Evaluation labels/private join files are retained separately from model-visible payloads; their directory name does not imply access isolation in the original execution.
3. Local home/project path metadata is replaced with explicit placeholders in derivative locks, manifests and source code. Original files stay read-only. SOURCE_TO_RELEASE_MAP.json records original and release SHA-256 values for every copied input. Derived pure provider helper code additionally records its source-parent hash.
4. Hosted raw-response derivatives keep final answer text, model/finish information and token usage, while excluding thinking blocks, signatures, safety/account metadata and unrelated provider envelope fields. Provider response/request IDs are hashed consistently; local research logical IDs and scientific hashes remain unchanged. Technical failure attempts and toy usage records are retained where the existing budget replay depends on them.
5. Credentials, setup scripts, environment directories, model weights/caches, unrelated conversations, Git internals, planning piles and obsolete full manuscript drafts are excluded by allowlist. No credential value was read for this task.
6. Historical path/hash adaptation is explicit: the replay first checks actual derivative bytes against MANIFEST.sha256 and the release map. It then resolves recorded historical file/configuration digests using validated original-to-derivative bridges. It filters omitted historical lock entries **in memory only**. Original and exported historical locks are not revised into new scientific locks. Omitted lock entries are reported, not claimed verified by a recipient.
7. HISTORICAL_HASH_BRIDGES.json stores only original/derivative canonical digests for metadata redaction. Numerical calculations, text/token/order/cache joins, model scales, thresholds, endpoint logic and bootstrap seed remain the archived implementations. A source digest is not represented as the byte hash of a sanitized derivative.
8. The staged payload is scanned as UTF-8/JSON/CSV/source text, decoded Parquet cells/schema metadata, non-pickle NPZ arrays, PDF metadata/text/URI annotations/attachment inventory, and PNG metadata. Known code-escape author-email matches and the scanner's own regex syntax are resolved as false positives. This is a best-effort scan, not a formal secret-free certification.
